# TFont v0.2.0rc1 — XML-first researcher acceptance candidate

**Status: source release candidate, not a published release.** This document describes a candidate wheel built from this repository at an exact commit. The latest verified GitHub Release is still [v0.1.1](https://github.com/alexsosn/ontoTF/releases/tag/v0.1.1), which does **not** contain the new XML catalog API. No PyPI installation or distribution is implied.

## User-facing capability under test

- Discover source-evidenced XML mapping categories across all corpus XML files installed in the wheel, without maintaining a per-corpus registry.
- Look up a native node/feature/value, reverse-find a reviewed ontology target, and find **category-level** correspondences in other corpora.
- Execute an exact reviewed selector on an **already loaded** compatible TF corpus via `resolve_nodes` and inspect source/corpus-version constraints.
- Preserve `native-only`, `ambiguous` and `unsupported` outcomes rather than converting a suggestive label into ontology equivalence.
- Keep the historical profile/bundle APIs for downstream callers, while the XML files are the mapping source of truth for the new API.

The source tree and wheel are not corpus downloaders, do not establish token or lexeme identity across corpora, and do not promise complete coverage of all seven ontology models. XML category lookup and the older verified-parent profile executor have distinct contracts.

## Acceptance already demonstrated on the candidate code line

[PR #415](https://github.com/alexsosn/ontoTF/pull/415) executed a **fresh wheel** in an isolated Python 3.12 environment outside checkout with the official Text-Fabric 13.1.1 loader and the original commit-pinned [ETCBC ExtraBiblical TF 0.2](https://github.com/ETCBC/extrabiblical/tree/9a56288e6777bad6328856acf055c780e65dd5d9/tf/0.2) data. The CI output reported 39,862 native word slots, 39,560 populated `g_word` tokens, 302 empty slots, 12,225 `sp=subs`, 723 `sp=nmpr`, and six BHSA Noun category correspondences. Wrong corpus-version arguments and ontology promotion of `sp=inrg` are negative checks.

Original revision-pinned URLs in CI provide a reproducible source acquisition path. Exact observed counts or a user-provided revision string do **not** authenticate the bytes in a separately supplied corpus directory.

## Candidate installation and example

Supported Python: **3.12–3.15** (at the CI gate). The candidate wheel must be built or downloaded from a **future, actually published** candidate release. For a local build from the exact tested source:

```sh
python -m pip install build
python -m build --wheel --outdir dist
python -m pip install ./dist/tfont-0.2.0rc1-py3-none-any.whl
python -m pip install 'text-fabric==13.1.1'  # optional corpus loader
```

After obtaining original corpus data separately and loading it using Text-Fabric:

```python
from tf.fabric import Fabric
from tfont import find_by_target, find_correspondences, resolve_nodes

# Replace this path with the original pinned ETCBC/extrabiblical TF 0.2 directory.
# The corpus data are obtained separately and never shipped in the wheel.
loaded_extrabiblical_api = Fabric(
    locations="/path/to/extrabiblical/tf/0.2", silent="deep"
).load("sp g_word")
if loaded_extrabiblical_api is None or loaded_extrabiblical_api is False:
    raise RuntimeError("Could not load the pinned ExtraBiblical TF corpus")

token = [
    row for row in find_by_target("http://purl.org/olia/olia.owl#Token", corpus="extrabiblical")
    if row.kind == "node" and row.node == "word" and row.feature == "g_word"
]
assert len(token) == 1
ids = resolve_nodes(loaded_extrabiblical_api, token[0], corpus_version="0.2")
print(len(ids))  # 39560 with the original pinned TF 0.2 corpus

links = find_correspondences(
    "extrabiblical", "bhsa", node="word", feature="sp", value="subs",
    source_version="0.2", target_version="2021",
)
print([(link.target, link.scope) for link in links])  # category only
```

The path must resolve to an independently obtained compatible source directory with its structural, section and text-format dependencies, not a downloaded wheel. See [the complete real-source script](../../scripts/acceptance/real_extrabiblical.py) and [README](../../README.md). Do not present `pip install tfont` as a supported PyPI command.
