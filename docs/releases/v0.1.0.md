# TFont v0.1.0

First executable, deliberately narrow common-ontology semantic slice for already-loaded Text-Fabric / Context-Fabric corpora.

## What works

- Load and validate three separately versioned production semantic bundles for ETCBC BHSA, ETCBC Syriac and ETCBC ExtraBiblical.
- Resolve one shared OLiA `Noun` semantic request to reviewed exact native plans and execute against already-loaded TF/CF APIs, returning deterministic node IDs with mapping/projection reviews, provenance, release and runtime-parent identities.
- BHSA and ExtraBiblical use `word.sp in {nmpr,subs}`; Syriac uses `word.sp=subs` because proper nouns are encoded within `subs` in the reviewed Syriac revision.
- Validate parent TF-payload identities and full reviewed runtime prerequisites before selecting nodes. All three production profiles require an exact parent; incompatible, stale or unverified inputs fail closed.
- Structural/cross-artifact validation, deterministic digests, semantic IR compilation, capability discovery, exact resolution and scalar/finite-set execution are public library functionality.

Pinned source data revisions: [BHSA](https://github.com/ETCBC/bhsa/tree/4db00e2157915495e1a4d3d57e41223df24775da) TF `2021`; [Syriac](https://github.com/ETCBC/syriac/tree/bb0eaa7e21b020a26b7566d2e495da9b1f84a919) TF `0.9`; [ExtraBiblical](https://github.com/ETCBC/extrabiblical/tree/9a56288e6777bad6328856acf055c780e65dd5d9) TF `0.2`. Shared OLiA revision: `d3bd4f1aef9047b33186bfb2a1795401f3f1a4a6`.

## Installation and first success

Requires Python 3.10+. Download the `tfont-0.1.0-py3-none-any.whl` asset from this GitHub release and install that local file:

```sh
python -m pip install ./tfont-0.1.0-py3-none-any.whl
```

For real corpus execution, independently install a compatible Text-Fabric / Context-Fabric implementation and provide an already-loaded corpus API plus matching local `.tf` data. The [README](../../README.md) gives a BHSA first-success example that hashes the *actual local files* and refuses version drift. TFont itself does not obtain those corpus files or load a corpus automatically. Do not use `pip install tfont` as a PyPI instruction until an actual PyPI publication exists.

## Known limitations and verification scope

- Exact OLiA `Noun` only for the three pinned revisions; no broader lexical/part-of-speech inventory, approximate mappings, same-corpus multi-binding composition, generic Boolean/SPARQL query, MCP transport, remote ontology dereference, identity/authority resolution, corpus acquisition or installation.
- The executor receives already-loaded APIs, and local TF data must match the reviewed parent digest. Other revisions require a separately reviewed profile; no bypass via user-provided fingerprints or plans.
- Continuous integration tests the full repository suite and clean-installed wheel on Python 3.10/3.12. Its three-corpus end-to-end acceptance uses **API doubles** to test the real public execution path and fail-closed parent drift; it does not download or execute the three actual source corpora. A separate real Context-Fabric smoke test covers the lower-level loaded API on a tiny sample. Thus corpus semantics rely on the pinned, independently reviewed I-009 evidence, not an assertion that live corpus data were tested in CI.
- GitHub Release asset is the supported v0.1 distribution channel. PyPI publication, wheel signatures and an automated corpus downloader are not part of this release.
