# Applicability research: source families, November 2026

This batch extends the partial, pinned [scoped applicability policy](data/scoped-applicability.json) after all nine real source inventories passed R-005 run [45816402169](https://github.com/alexsosn/ontoTF/actions/runs/45816402169). It does not publish ontology targets. A review domain is a native family whose meaning warrants evaluation against that model; a candidate may later be found unsuitable. One authored XML mapping file remains sufficient for ordinary mapping contributions.

## Ontology definition checks

* [CRMtex 2.0](https://cidoc-crm.org/extensions/crmtex/html/CRMtex_v2.0.html): TX1 is physical written marks (E25); TX7 is a physically written text segment; TX8 is an abstract grapheme type, TX9 a glyph. Distinguish representations, abstract graphemes and physical objects before mapping.
* [CIDOC CRM 7.1.3](https://cidoc-crm.org/sites/default/files/Documents/cidoc_crm_version_7.1.3.html): P46 physical composition requires physical endpoints; P1 identification requires actual CRM entity/identifier roles; P2 type assignment is not equivalence to a raw catalogue string. These guide review of ORACC metadata and TLHdig joins.
* [LRMoo 1.1.1 R5](https://cidoc-crm.org/extensions/lrmoo/html/LRMoo_v1.1.1.html): structural meaningful components of an Expression; arbitrary line/page boundaries use different properties. Do not equate join apparatus with expression derivation (R76).
* [CRMinf 1.2.1](https://cidoc-crm.org/extensions/crminf/html/CRMinf_v1.2.1.html): I2 concerns belief in a proposition set by an actor, I5 inference making concerns premise/conclusion and logic, I6 the belief value. Editorial flags or algorithmic resolution statuses alone do not supply those structures. Route review candidates to CRMinf, not positive inference events.
* [OntoLex-Lemon](https://www.w3.org/2016/05/ontolex/) distinguishes entry, form and sense; [SKOS](https://www.w3.org/TR/skos-reference/) requires concept/label identity rather than a literal automatically becoming a concept; pinned [OLiA](https://github.com/acoli-repo/olia/tree/d3bd4f1aef9047b33186bfb2a1795401f3f1a4a6) distinguishes morphology/syntax categories and graphological annotations.

## Explicit granularity exclusions

The policy distinguishes separately researched exclusions from simply unclassified observations. TLHdig `anchor` is documented as a technical empty slot marker, `subcorpus` as a compatibility alias of `project`. Pseudepigrapha and ORACC source byte digests serve integrity/provenance, not separate native semantic mapping obligations in this project. ETCBC native morpheme spellings and Peshitta witness labels are assessed at feature granularity; their individual values are retained in the empirical census but excluded from this applicability denominator. These exclusions are scoped to the project's present category mapping goals and do not claim these metadata could never be represented in an ontology.

## Remaining research

The policy is partial, even when all observed directed edge pairs have review routes. In particular many open-valued features and source-specific metadata remain unclassified. Review them by source family, distinguish genuine categories from spellings, identities, technical fields and alternate encodings, and document excluded/unknown separately. Do not force unsupported ontology targets. Complete the candidate selection and evidence checks in parallel with actual mapping batches; the policy is research evidence for the dashboard, never a new contribution gate. Guarded selectors are currently reported separately from whole node types, so guard-specific eligibility still requires separate interpretation rather than inflating unconditional node-type counts.
